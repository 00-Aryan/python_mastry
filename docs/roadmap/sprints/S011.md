## Implemented verification responsibilities

`tests/integration/recovery_wire.py` is a loopback-only, one-shot COMMIT-reply-loss
proxy. It buffers bounded PostgreSQL backend frames and withholds CommandComplete
(COMMIT), then closes the client socket. It does not interpret results or log packets.
[PostgreSQL message formats](https://www.postgresql.org/docs/18/protocol-message-formats.html)
define this frame; durable state is also checked using an independent connection.

`recovery_worker_process.py` starts a real production EvaluationWorker/LocalIsolatedRunner
in a separate process, with SystemClock, authenticated test credentials and mandatory
startup checks. SQLAlchemy hooks only arm the wire fault; no production method/result
is replaced. Actual SIGKILL barriers occur after real isolated learner entry or after
real completed dispatch. `test_real_recovery.py` owns independent database observations,
real timestamp waits, restart/replay/stale-lease/revocation assertions and cleanup.
No learner source enters the trusted process as executable code.
