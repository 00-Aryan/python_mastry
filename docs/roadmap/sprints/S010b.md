## Ordering decision before implementation

An execution validates its pinned runtime and bounded payload, starts the isolated
service, and completes mandatory live control validation before considering readiness.
A cancellation request during validation is latched; it does not kill that validation
out from underneath the verifier. Genuine validation errors retain precedence. Once
controls pass, explicit cancellation is checked before/after waiting for READY and at
the serialized source-write boundary. No source is sent after an accepted cancellation
at that boundary. Observed malformed/missing readiness without earlier accepted
cancellation remains a genuine bootstrap error; later cancellation cannot rewrite it.

External cancellation is distinct from stopping a unit for resource enforcement or
finally cleanup. It remains latched on that sandbox instance; reusing it must not erase
a stop request. Resource failures already observed keep their resource classification.
Single-worker sequential execution is retained; no parallel executions share a sandbox.
Worker authentication, policy pins, leases and public result categories are unchanged.
Deterministic event barriers will replace timing assumptions in phase tests; real
execution and subprocess substitutes will be reported separately.
