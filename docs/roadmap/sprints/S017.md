### Findings against the pilot specification

1. **Independent reasoning versus reproduction.** A01 requires a presence fact
   separately from the selected value. P01's integer result alone cannot determine
   that fact when a present value equals the fallback. The authored contrasting
   cases and value-derived/truthiness-derived incorrect programs exercise this
   difference; the private audit retains their exact inputs and sources. This is
   more than renamed variables or different data, and matches S016's explicitly
   permitted presence-versus-equal-fallback example. However, an acceptable P01
   membership/branch solution already makes the decision that A01 returns. Adapting
   its return values is straightforward. S016 also rejects cosmetic wrappers and
   groups substantially the same solutions. The counterexample establishes output
   distinguishability, not by itself the stronger claim that the pair demands
   independent reasoning after every permitted P01 solution/help path. Human review
   must weigh that actual overlap rather than approve solely from the counterexample.
2. **Family assignments.** P01 correctly stays in `DICT-LOOKUP-S015`
   (`15000000-0000-0000-0000-000000000031`): its core task is S015's lookup/default
   practice. A01's proposed `DICT-LOOKUP-PRESENCE`
   (`17000000-0000-0000-0000-000000000031`) describes the changed observable contract
   allowed by S016, but its unseen-assessment acceptance remains provisional for
   the reason above. A UUID and first-family flag cannot resolve that concern or
   grant independent evidence. Existing published history must stay immutable; an
   adverse family review requires versioned authoring rather than reassignment of
   historical family facts.
3. **Examples, hints and prior exposure.** A01's public examples show the required
   output shape and ordinary present/absent semantics. Its statement explicitly
   explains the equal-fallback distinction, so it tests implementation of that
   stated rule, not unaided discovery of the distinction. Examples do not reproduce
   its private contrasting cases or include reference source. Its own hint ladder
   intentionally progresses to an algorithm and full solution through owned,
   irreversible grants; assisted performance is not unaided evidence. More
   significantly, P01 (and S015) hint stages 2–4 already teach membership, branching
   and value/default selection. That prior help can make A01 a near-direct
   adaptation, despite a new family ID. This is an exposure risk, not proof that
   any particular learner received those grants. The public repository also exposes
   authoring answers to source readers; API privacy cannot guarantee an unseen
   assessment for them. No current score or runtime eligibility claim is added.
4. **Observable rubrics and roles.** P01's rubric observes stored-value/default
   selection, including zero and negatives, and is correctly practice-only. A01's
   rubric observes an exact boolean presence flag and integer value, including
   equal-value presence distinctions; it remains an assessment-only **candidate**.
   The existing checks distinguish integer flags from booleans and exercise falsey
   values. Both use one primary D1 skill; there is no automatic secondary-skill
   evidence. Non-mutation, complexity, explanation quality, arbitrary nested/input
   semantics and human competence are not established by finite return-value
   tests. The references use read-only operations, but that does not certify all
   learner programs. These stated limits are consistent with the assigned roles;
   the unresolved item is novelty/exposure, not executable rubric observability.
