## Authoritative scope and acceptance map

The canonical roadmap S012 requires a trusted verifier around immutable authored
snapshots, test bundles, reference solutions and evaluator versions. Reports must
store content hash, verifier identity/version and bounded results; unavailable
verification cannot approve publication. Prerequisites are the existing question
snapshot/authorization rules and locally verified B6b isolation (S010a/S011).

This unit adds an explicit, separate local admin CLI invocation, not API execution
or an operational worker. It captures canonical draft bytes/revision in a short
transaction, runs the reference against authored examples/tests in fresh existing
B6b sandboxes outside all transactions, then appends a durable immutable report.
It pins the entire snapshot, bundle/reference hashes, verifier version and immutable
runtime/evaluator policy. No hidden value, source or exception text is in results.

Resolved scope boundary: a passed S012 report means the reference matched this
bounded bundle, not that tests are strong or the question is publishable. S013
owns consumption of reports and publication revalidation; the existing default
publication verifier remains unavailable (503). S014 owns richer contract/example
quality and representative incorrect solutions. No new publication bypass.

Acceptance checks: real PostgreSQL upgrade from 0008, immutable reports and pins,
rollback/revoked admin, stale revision, snapshot preservation across later edits,
real isolated passing/failing/invalid reference and unavailable controls, bounded
results and payloads, no private diagnostics, unchanged 503 publication; complete
PostgreSQL/isolation, cancellation/recovery regressions, locked sync, Ruff, format,
strict mypy, migrations and package checks. Unavailable attempts produce a
non-approving report where a snapshot can be captured; no partial success on error.
